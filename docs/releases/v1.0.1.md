# RustInfer v1.0.1

RustInfer v1.0.1 is a correctness and release-readiness update for the LLM
serving stack. It preserves the three-process architecture while fixing unsafe
tensor views, CUDA graph resource lifetime issues, request lifecycle failures,
sampling, stop sequences, and browser streaming.

## Supported scope

- Llama 3 and Qwen 3 decoder models
- Dense BF16 and Qwen 3 AWQ W4A16 weights
- OpenAI-compatible chat and text completion endpoints
- Streaming and non-streaming responses
- CUDA inference; the CPU backend remains the reference implementation used by
  tests

Diffusion was experimental and is disabled in this release. Configurations must
use `mode = "llm"`; unsupported image routes and Z-Image diagnostic scripts are
not shipped as release functionality.

## Upgrade notes

- All workspace crates now report version `1.0.1` and are explicitly marked
  `publish = false`; this release is distributed as a repository/application
  release, not as crates.io packages.
- The HTTP server binds the configured `host`. The sample configs use
  `127.0.0.1`; set an external interface deliberately when remote access is
  required.
- Replace each sample config's `./models/...` value with the local Hugging Face
  model directory before launching.
- The repository pins Rust 1.91.1. Rustup selects it automatically through
  `rust-toolchain.toml`.

## Build and verify

```bash
cargo fmt --all -- --check
cargo test -p infer-core -p infer-backend-cpu -p infer-protocol \
  -p infer-scheduler -p infer-server
cargo test -p infer-worker --no-default-features --lib
cargo build --release
scripts/e2e_smoke.sh run_qwen3.toml 8100
```

The hosted CI gate exercises the GPU-independent build. A release operator must
also build and run the end-to-end smoke test on a supported CUDA host with the
CUDA toolkit, cuDNN runtime, and cuDNN frontend headers installed.
